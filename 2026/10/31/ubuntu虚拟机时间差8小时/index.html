Ubuntu 虚拟机时间比主机差 8 小时：时区与 NTP 排查

虚拟机里的 Ubuntu 时间与主机正好差 8 小时，这是个很经典的问题。它通常不是「时间不准」，而是时区配置不一致加上同步服务没开。

原因分析

  1. 时区差异（最常见）：主机用的是 Asia/Shanghai（UTC+8），而虚拟机装机时往往默认 UTC，两者正好差 8 小时。
  2. 硬件时钟解读方式不同：Linux 默认把硬件时钟（RTC）当作 UTC，Windows 主机通常当作本地时间。虚拟机启动时从主机同步了 RTC，Ubuntu 却按 UTC 解读，偏差就出来了。
  3. 时间同步服务未启用：虚拟机长时间运行后，CPU 调度会让时钟漂移，没有 NTP/Chrony 校准，时间会越走越偏。

虚拟机的额外建议

虚拟化平台 推荐操作
VMware 安装 open-vm-tools，内含专门的时间同步模块：sudo apt install open-vm-tools
VirtualBox 安装 Guest Additions 后，勾选「同步客户机时间」
Hyper-V 安装 linux-tools-virtual 和 hyperv-daemons
KVM/QEMU 确保宿主机时间准确，Guest 内用 chrony 即可

最佳实践：虚拟机内的时间同步应优先依赖虚拟化平台提供的工具（如 VMware Tools），其次才是 NTP。平台工具能感知 VM 的暂停/恢复事件，避免恢复后出现巨大的时间跳变。

补记：有时一行 set-ntp true 就够了

后来遇到一次，sudo timedatectl set-ntp true 直接解决了问题。这种情况说明时区本身是对的（已经是 Asia/Shanghai），纯粹是 NTP 同步服务之前处于关闭状态。

为什么这行命令有效：

  • 虚拟机受 CPU 调度、挂起/恢复影响，硬件时钟漂移比物理机快得多
  • NTP 服务被禁用时，系统只能依赖这个不稳的虚拟硬件时钟，时间很快偏离
  • set-ntp true 重新拉起 systemd-timesyncd，它会立即向 NTP 服务器请求准确时间并完成校准

2. 检查虚拟化增强工具是否安装

  • VMware：sudo apt install open-vm-tools
  • VirtualBox：安装 Guest Additions
  • Hyper-V：sudo apt install hyperv-daemons

这些工具能在虚拟机从「暂停 / 快照恢复」的瞬间完成时间修正，比纯 NTP 响应更快、更可靠。
